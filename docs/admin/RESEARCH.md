# Research and implementation direction · merchant operations

The repository and Stage 1 contracts, fonts, image handling, responsive shell and QA harness were inspected first. The findings and implementation plan below were presented before the Stage 2 route split or development. No merchant records or third-party store imagery were used as design assets.

| Source examined | Decision for PARADELLE |
|---|---|
| [Shopify Build Awards merchant apps](https://apps.shopify.com/stories/guide-build-awards-2026) | The operational lesson from Easyteam is to keep staff work in the merchant's existing context. Use one app, one store and a consistent admin shell, rather than an independent SaaS dashboard. |
| [Shopify index-table compositions](https://shopify.dev/docs/api/app-home/latest/patterns/compositions/index-table) and [Polaris data-table migration patterns](https://shopify.dev/docs/apps/build/app-home/migrate-from-polaris-react/data-table.md) | Separate browsing a register from comparing metrics. Put search/filter/sort before rows; name the selection scope and preserve sort on narrow screens. Reset pagination on filter changes. |
| [Shopify order statuses](https://help.shopify.com/en/manual/fulfillment/managing-orders/order-status) and [inventory adjustment history](https://help.shopify.com/en/manual/products/inventory/adjusting-inventory/adjustment-history) | Payment is not fulfilment. Show the provider record separately from manual Meesho purchase and delivery. Require adjustment reason, actor, timestamp, before/delta/after per size. |
| [AI-assisted product descriptions](https://help.shopify.com/en/manual/products/details/product-descriptions/shopify-magic) and [media generation guidance](https://help.shopify.com/en/manual/shopify-admin/productivity-tools/shopify-magic/media-generation) | Treat generated text and art as suggestions. Keep verified source evidence visible. Do not fill missing attributes, licence assumptions or customer testimonials with generated content. |
| [fal reference-editing queue API](https://fal.ai/models/fal-ai/flux-2-pro/edit/api) | Send only authorised references from a server worker. Use a queue, stored request IDs, discrete square outputs and a review gate. A queue acknowledgement is not an image, a publication or a completed refund. |
| [NN/g: reducing cognitive load](https://www.nngroup.com/articles/4-principles-reduce-cognitive-load/) and [interaction response times](https://www.nngroup.com/articles/response-times-3-important-limits/) | Break a long import into named decisions. Show current work immediately; don't invent progress percentages. Put costs and margin assumptions next to the recommendation. Retain reversible drafts and confirm destructive decisions. |
| WAI tutorials: [form validation](https://www.w3.org/WAI/tutorials/forms/validation/), [tables](https://www.w3.org/WAI/tutorials/tables/), [complex images](https://www.w3.org/WAI/tutorials/images/complex/) | Use labels and textual errors, scoped column headers, keyboard-aware overflow and stacked rows. Give charts an accessible description plus the exact underlying values. |
| Next.js: [route groups](https://nextjs.org/docs/app/api-reference/file-conventions/route-groups), [authentication](https://nextjs.org/docs/app/guides/authentication) | Keep the font/document root. Split public chrome from the admin workspace without changing shopper URLs. Verify session **and** permission at every private data read and Server Action, not just the layout. |
| Supabase: [server-side Next.js auth](https://supabase.com/docs/guides/auth/server-side/nextjs), [Postgres RLS](https://supabase.com/docs/guides/database/postgres/row-level-security), [storage access control](https://supabase.com/docs/guides/storage/security/access-control) | Define a server-only session boundary now. Stage 3 must enforce verified claims, explicit grants, RLS and private object policies. Never use a service-role key as browser authentication. |

## Design and build sequence

1. **Shell and contracts:** retain Cormorant Garamond, DM Sans and the storefront palette. Use an espresso rail, ivory workspace, restrained status colours and a decorative textile still life. Separate disconnected, genuinely empty, forbidden, missing and failed results.
2. **Catalogue and operations:** build the product, inventory, sales and settings registers on shared keyboard-operable components. Expose selected-row scope and a reason for sensitive changes. Use native drawers/dialogs and sectioned forms on smaller screens.
3. **Import studio:** source permission → evidence → listing → five frames → review permission → transparent pricing → final approval → job tracking. Every persisted step belongs to a job/revision. Manual facts are available without any access workaround.
4. **Verification and handoff:** run the production route/viewport matrix, form and interaction checks, privacy/role boundary checks and the existing storefront regression suite. Deliver real screenshots of the unconfigured state, API schemas and the provider release checklist.
