# Stage 3 provider contract · private merchant service v1

**Deliverable:** the frontend and server adapter, not a provisioned database or provider. [OpenAPI 3.1 JSON](openapi.json) enumerates all 22 HTTP paths, response envelopes, filters, field types, enums and 20 command variants. Regenerate it with `npm run contract:admin`. The [runtime schemas](../../lib/admin/models.ts), [command schemas](../../lib/admin/commands.ts) and [business checks](../../lib/admin/rules.ts) are authoritative. This document supplies the cross-field, authorisation and transaction semantics JSON Schema cannot express.

## Transport and access

Implement these handlers in the **same single-store deployment**, for example under `/api/private/v1`. Set `PARADELLE_ADMIN_API_URL` to its absolute trusted prefix. The adapter accepts HTTPS (HTTP loopback for local development/testing only), refuses redirects and uses an eight-second request timeout. Browser JS calls **same-origin Next Server Actions**, not this service, Supabase admin, Razorpay or fal. Longer operations must enqueue work. No tenant ID or client-selected actor is accepted.

| Auth path | Contract |
|---|---|
| `POST auth/login` | `{email,password}` → `{token,expiresIn}`. Authorised staff only, generic failure and rate limits. Token is an opaque handle, 20–4096 allowed URL-safe characters; lifetime seconds `1..86400`. Adapter checks `auth/session` **before** issuing the browser cookie. No signup. |
| `GET auth/session` | Server bearer handle → `{id,name,role:'admin',permissions:Scope[]}`. Verify claims, expiry, revocation and current grants with the authority. Never trust editable user metadata or a decoded-but-unverified JWT. |
| `POST auth/recover` | `{email}` → `202`, uniform for eligible/ineligible addresses; actual protected recovery delivery is Stage 3. Configure allowlisted HTTPS return/callback URLs, one-use recovery and revocation. Never disclose account existence. |
| `POST auth/logout` | Revoke the handle; `204`. The adapter always expires its local cookie, even if the upstream service is unavailable. |

Use `paradelle_staff` with **HttpOnly, Secure, SameSite=Strict, Path=/admin**, no Domain attribute. Keep any Supabase access/refresh material behind the opaque session. Rotate/revoke it and enforce absolute expiry; never log passwords, handles, recovery tokens, signed image URLs or customer data. Independent verification at both adapter and provider is intentional. `catalogue`, `imports`, `orders`, `inventory`, `customers`, `pii`, `reviews`, `analytics`, `settings` are distinct permissions. Configure least privilege, database grants/RLS per operation, and private storage policies. A logged-in shopper or an unprivileged staff account is not an admin grant.

Admin documents carry `private, no-store`, `no-referrer`, `noindex, nofollow`; `/admin` is not in the public sitemap. These directives are **not access controls**. Private Server Action responses/HTTP reads must not be CDN- or service-worker-cached. Empty configuration renders an **unpopulated workspace only**; a configured service requires verification, and an outage does not downgrade to a trusted or writable mode.

## Reads

`id` is an opaque bounded `Key`, never an email, a mobile number or a filesystem path. All amounts are integer **INR paise**; rates are integer **basis points**. Report calendar dates use `Asia/Kolkata`; event timestamps are ISO 8601 with timezone. Unknown optional amounts/rates are `null`, not zero. Return numbers only when they are computed from genuine records.

| Method and path | Response | Required permission(s) |
|---|---|---|
| `GET dashboard?days=7\|30\|90` | `Dashboard`: summary, daily sales, ≤10 orders without mobile, ≤20 audit entries | `analytics`, `orders`, `pii` |
| `GET analytics?days=7\|30\|90` | `Analytics`: financial aggregates, dated series, product units/category net sales/status counts | `analytics` |
| `GET products`, `GET products/{id}` | `ProductRowPage`, `Product {id,revision,status,updatedAt,draft}` | `catalogue` |
| `GET pricing/defaults` | `Costs`; null fields when an assumption is not configured | `catalogue` |
| `GET imports`, `GET imports/{id}` | `JobRowPage`, full `Job` including version, stages, facts, references, editable draft, suggestions, frames, reviews and errors | `imports` |
| `GET orders`, `GET orders/{id}` | `OrderRowPage`, `Order` with protected address, provider record, immutable item snapshots, manual purchase data, outstanding refundable balance and history | `orders`, `pii` |
| `GET inventory`, `GET inventory/history?limit=25` | `StockPage` (one row per size plus authoritative product stock), newest `Adjustment[]` with `before + delta = after` | `inventory` |
| `GET customers` | `CustomerPage` derived from genuine purchases; `/admin/orders?customerId=…` reads the authorised history | `customers`, `pii`; order history also requires `orders`, `pii` |
| `POST orders/search`, `POST customers/search` | `PrivateSearch {q,status,category:'',sort,page,customerId}` → corresponding page. Names/mobile search in the body, not the browser URL, a query log or persistent storage. | Same as corresponding register |
| `GET reviews` | `ReviewPage`: linked product, source, permission, rating, moderated state and actual purchase verification | `reviews` |
| `GET settings` | `{revision,value:Settings}`. Profile belongs to the authenticated actor. Do not include any provider credentials. | `settings` |

**Register envelope:** `{rows,total,page,pageSize}`; 1-based page, maximum 50 rows, `total` is the count after filtering across all pages. Apply search/filter/sort **before** pagination; use a stable ID tie-breaker. Bound out-of-range pages. Return a genuine empty page for a successful empty query. Missing record `404`, unavailable endpoint `5xx`, invalid session `401`, insufficient permission `403`, throttled `429`. Invalid payloads/timeouts are errors, not empty populations. Return minimised/masked contact fields where the task does not require full details. Do not ship raw event payloads.

**Filters:** [OpenAPI](openapi.json) lists exact query names and enumerations per register. `paid` means successful payment, fulfilment filter values are `pending-purchase`, `ordered-on-meesho`, `shipped`, `delivered`, `cancelled`; refund states filter the payment dimension. `out-of-stock` is zero, `low-stock` is positive at/below the configured threshold, `disabled` is not purchasable. Import categories describe the current job, not publication of an unrelated product. Only public-safe catalogue queries are shareable; text searches on customer/order pages are POST-only.

**Measurement definitions:** `days` is the inclusive reporting window ending today in IST. Paid revenue is captured consideration for the window; paid/pending order counts use the corresponding payment state and order date. Published/low-stock-product and waiting-approval counts are **current distinct counts**. For reporting: gross = item selling value before discounts/refunds on captured orders; net = gross less discounts and completed merchandise refunds, excluding GST and shipping income. Orders = distinct qualifying captured orders; AOV = net/order count or null with no denominator. Contribution = net less actual sourcing/variable fulfilment/payment/returns costs, null if inputs are incomplete. Return/refund rates use distinct affected orders divided by qualifying orders in the same cohort; null if not defined. Sales series must be dated; aggregate to Monday-start weeks/calendar months without inventing observations. Return segment values and counts in their named units. Do not treat a pending refund as settled.

## Mutations and audit

`POST commands`, JSON discriminated by `op`, requires header `Idempotency-Key: <UUID>`. `Ref = {id,revision}`; each update compares the **current** revision within the transaction. Deduplicate by actor/operation/key and body hash, commit at most once, return the stored receipt on a replay. Reject a key reused with different input. `409` for stale revisions; `422` for invalid state, amount, required field, rights or stock; `429` for limits. Do not trust a browser price, computed total, image URL, verification tick or permission label as proof.

Success body: `{id,revision,eventId,outcome:'applied'|'queued'}`. `200/201 + applied` only after a durable commit; `202 + queued` only after a durable background task exists. A bare `ok:true`, a redirect or a job still running cannot be used as publication/payment confirmation. For an import start/retry the `id` identifies the job, not the worker request. For product save/duplicate/import finish, `id` identifies the resulting product. For bulk transitions return a durable batch ID/revision/event; the client reloads the register. Commit the domain change, audit entry and any worker outbox entry atomically.

| `op` | Additional fields | Provider behaviour |
|---|---|---|
| `product.save` | `ref:Ref\|null`, `draft:Draft`, `intent:draft\|publish\|update` | Create or edit; verify media ownership, variant/slug/SKU uniqueness, finite integral paise/stock, required publication evidence. Published updates repeat publication checks. |
| `product.transition` | `refs:Ref[1..50]`, `to:draft\|published\|archived` | Distinct explicitly selected IDs only. Validate **every** record/revision, including full publish validation; all-or-nothing with per-record audit. Never apply to a whole search by implication. |
| `product.duplicate`, `product.delete` | `ref` | Duplicate only an existing record into a **new draft**, with new IDs, no copied inventory/SKUs/publication approvals. Reject unsafe deletes; preserve order snapshots and legally required history. |
| `stock.adjust` | `ref` (variant), non-zero integer `delta`, `reason` | Lock variant, check revision and bounds, append actor/at/reason/before/delta/after, recompute total/alerts. Not a Meesho stock sync. |
| `order.fulfil` | `ref`, `manual:ManualFulfilment` | Record manual status, source link, Meesho purchase ref/cost/date, carrier, tracking ref/link and notes. Validate transition/current order; purchased states require real purchase details; shipped/delivered require tracking. Never infer a captured payment. |
| `order.refund`, `order.check-refund` | `ref`; initiation additionally `amountPaise,reason` | Authorise original payment, captured amount and remaining refundable balance; deduplicate and **queue** the provider operation/check. Only signed provider evidence changes settled state. Log request, subsequent status and actor/source. |
| `review.moderate` | `ref`, `to:published\|unpublished\|rejected` | Check linkage/provenance and permission. Only a matched genuine order can verify a PARADELLE purchase. Do not rewrite a rating/testimonial. |
| `settings.save` | `revision,section,value` | Schema for `value` is exactly `Settings[section]`. Patch **only this section**. Check HTTPS links, business content and permissions; require separate provider verification for admin email changes, not arbitrary role changes. |
| `import.start` | `url`, `method:extract\|manual`, `authorised:true` | Create a resumable job. `extract` is **queued**, `manual` is applied without fetching. Record rights/provenance assertions, enforce actual access independently. |
| `import.facts` | `ref,facts:Fact[]` | Persist field/value/origin/verification, including explicit missing values. Manual edits reset verification. Evidence changes invalidate derived approvals as necessary. |
| `import.content`, `import.save-listing` | `ref`; save additionally `draft` | Generation is **queued** against verified, non-empty facts only. Save suggestions separately; applying them is a human edit, not approval. Persist listing/variants/SEO/pricing in the job for resume. |
| `import.images` | `ref,referenceIds,rightsConfirmed:true` | **Queue** exactly five initial square slots once. Check reference ownership/licence and purpose. Never accept an arbitrary remote fetch URL as an asset. |
| `import.image` | `ref,slot:0..4,action:regenerate\|remove\|approve`; `alt` required for approval | Regenerate is **queued for that slot**, not five new frames. Remove clears the output/approval but retains the slot. Approval requires a ready square photo, source rights and visual fidelity review. |
| `import.review` | `ref,id` (review in this job), `approved:boolean` | Include only permission-granted, sanitised source reviews, never a generated review. Clearing approval is reversible. |
| `import.finish` | `ref,draft,intent:draft\|publish` | Create/update one product transactionally. Draft stays private. Publish rechecks approved evidence, five distinct matching frame IDs, square dimensions, verified listing, actual price, valid sizes/SKUs and review rights. Only the authorised admin's explicit final approval publishes. |
| `import.cancel`, `import.retry` | `ref`; retry additionally `stage:extraction\|content\|images\|reviews` | Cancel marks job closed, best-effort cancels pending work and rejects late results. Retry **queues only a failed stage**, preserving valid work and the job ID. A restricted source is not a retry target; use manual evidence. |

Command scopes: `product.* → catalogue`; `stock.* → inventory`; `order.* → orders + pii`; `review.* → reviews`; `settings.* → settings`; `import.* → imports`, with `import.finish` additionally requiring `catalogue`. At commit time verify every object is in this store and the actor may change it. No administrative command sets an order to paid or places a Meesho order.

`POST media` takes multipart `{purpose:product|reference|logo,rights:'confirmed',file}` → `201 Photo {id,src,alt,width,height}`. Require `catalogue`, `imports` or `settings` respectively. Single file ≤4 MiB, JPEG/PNG/WebP; frontend checks size/type and signature. **Provider must decode, bound dimensions/resource use, strip metadata, sanitise/re-encode, apply bucket policy, and issue a short-lived private URL or guarded same-origin path.** Expire unattached uploads; never publish a private bucket or cache a signed URL in a public image optimiser. Local blob previews are not uploads.

## Import worker and human checks

- Persist job, input URL, rights evidence, actor, timestamps, revision, stage statuses, bounded sanitised error text and provider request IDs (IDs/keys used to call fal stay server-side). Restrict source navigation to permitted HTTPS Meesho product pages and revalidate every redirect; honour licence, terms and access restrictions. No session harvesting or access workarounds. Restricted/missing information → manual fact sheet.
- For content, retain original source values and provenance. Do not infer missing textile composition, sizes, construction, care or benefits from an image. Listing suggestions may use only verified evidence. A human may edit and verify them before publishing.
- Reference-conditioned image generation uses business-authorised input. In order: **main product view, lifestyle, alternative pose, fabric/detail, additional presentation**. Each is square and reviewable independently. Preserve colour, print, pattern, embroidery, neckline, sleeves, garment length and construction. No display/publish of failed outputs as successful images. Regeneration invalidates approval.
- Collect a maximum of ten eligible reviews from an authorised source during the permitted job stage. Do not collect reviewer PII. Pending/denied rights may carry status/source only (`body:''`, `rating:null`, not approved); do not store or emit the text before clearance. If unavailable, `reviews:[]` is correct. Native PARADELLE reviews are a **different stream**, moderated against actual purchase evidence.
- Submit a queue request, persist acknowledgement, then process signed webhooks or poll provider status in a worker with bounded retries/backoff. Deduplicate callbacks and ignore superseded slot revisions. Limit cost and concurrency per job. Frontend polls a running selected job at 4.5-second intervals only while visible, avoids overlapping reads, stops on failure/terminal state, and offers manual refresh. It does not keep a generation HTTP request open or show a fabricated percent.
- Reopening `?job=<id>` reloads saved facts, listing, references, outputs, approvals and task state. Unsaved form text is intentionally ephemeral. Persist edits explicitly, append the audit events, and refuse stale/closed jobs. After publication, project a public product; never expose source pricing, bookkeeping or customer details.

## Pricing and public projection

For a unit, `C = source + extras + packaging + shipping + feeFixed + reserve`. Other blank cost components are **explicitly excluded** from the estimate. Sourcing cost, target margin and tax treatment are required for a recommendation. Let `t` be inclusive GST rate or zero for “no GST modelled”, `f` the payment fee on gross selling price, `m` the target contribution margin on net revenue. For selling price `P`, net revenue `N=P/(1+t)`; contribution `N−C−fP`; margin `contribution/N`.

Minimum/recommended/premium solve `ceil(C / ((1−m)/(1+t)−f))` in **paise**, with `m=0`, the chosen target, or target + five percentage points. The implementation uses integer basis-point arithmetic before ceiling. Non-positive denominators are not feasible. Optional ₹99 endings round upward only if the uplift is ≤10%; minimum is not cosmetically rounded. Actual selling price is entered/applied deliberately. No automatic MRP, discount, tax assurance or promised profit.

Public `catalogue`/`settings` remain separate ([public contract](../INTEGRATION.md)). Expose only published, approved assets and enabled variants with real stock, public copy/SEO and the approved selling price. Map category/style/fabric/specifications truthfully, omit unsupported claims. Native verified reviews go into `reviews`; optional `sourceReviews` are separately labelled with required source/granted permission/approval, no reviewer name and no purchase-verification badge. They are never featured as homepage customer testimonials. Only pass approved public settings; do not pass admin profiles, costs, reserves, secrets or private audit data. Confirmed catalogue/stock/moderation changes expire the public catalogue cache tag; confirmed settings changes expire the public settings tag. Provider callbacks must also invalidate affected projections after durable changes.

## Before enabling production

1. Provision Supabase Auth with no public admin registration, restricted staff grants, migrations/RLS, private Storage, session refresh/revocation, recovery delivery and verified callbacks. Test two staff grants and unauthorised direct reads/actions.
2. Implement the read projections/validated command transactions and append-only audit events; enforce integrity, idempotency, redaction, record-level authorisation, pagination and optimistic concurrency at the database/service boundary.
3. Configure a rights-cleared product/evidence source, private reference assets, fal credentials/queue worker and webhook verification. Prove cancel/retry/resume, five-frame fidelity and human publication checks using genuine authorised material.
4. Connect Razorpay server credentials and verified capture/refund webhooks to actual orders. Reconcile signed events; test failures, duplicates and partial refunds in the provider's authorised test environment. Keep purchase and shipping manual.
5. Supply approved business settings, genuine catalogue/variants and policies. Use HTTPS, exact media/return origins, rate limits and secret/log hygiene. Run [staging acceptance](QA.md) before enabling public checkout or publishing a record. No keys or genuine customer/order data were supplied or committed in Stage 2.
